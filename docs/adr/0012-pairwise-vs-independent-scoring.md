# 差距报告用「独立打分再作差」,而非「成对直接对比」

多人评测系统上线后,一道任务会同时产出 Violoop 与竞品的交付物,PM 想要一份「差距报告」。直觉架构是让一个 AI 同时看两份交付物直接对比(`report = compare(A, B)`)。我们拒绝这条路,改为:每份交付物**各自独立**跑现有评测引擎(GATE → 客观断言只看末态事实 → 盲评面板 S1-S5 → H1 诚实度),再对分数作差,大差距那条自动生成 Finding,开源竞品附源码机理分析。「差距报告」= 分数差 + Finding + 机理分析,不是单次成对对比的自然语言输出。

## 为什么

「成对直接对比」会丢掉三样立身之本:①客观断言层(消息到底发出没,不靠 AI 观感);②黄金集 kappa 校准(校准锚点是「单份交付物→期望分」,成对对比无法校准);③每份独立盲评。独立打分再作差全部保留,且产出对 PM 不变(仍是「谁强多少、强在哪」),只是可信度地基不动摇。

## 代价

「差距」不是一次调用直接得到的叙事,而是引擎跑两遍后的派生量;需要下游把「分数差 + Finding + 机理分析」组织成 PM 能读的报告视图(新增的报告层,而非新增审核逻辑)。
