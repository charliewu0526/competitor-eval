# 领取粒度 = 一道对比任务的全部,由一人一次性完成

竞品对比里,一道题要在 Violoop + 同域竞品上各跑一次。「谁跑的」本身是个变量。两条路:①一人包全部产品(简洁,但同一人跑自家顺手、跑不熟竞品糙 → 系统性偏向自家;且数据点无副本);②拆给不同人跑不同产品(降执行偏差,但协调重、违背 PM 定的「一题一人」简洁意图)。

决定:**领取的最小单元 = 一道对比任务的全部(Assignment)**,同一个实习生一次性跑完这道题的 Violoop + 全部同域竞品,产出 N 份 Submission。执行偏差(Runner Bias)作为**已接受的残余风险**,不靠多人重复消除,而靠三道兜底:标准 Prompt(减执行差异)+ 执行日志包(暴露异常执行)+ 盲评(面板不知谁是自家)。

## 代价

单点数据无交叉副本:抽查发现某 Assignment 有问题时,只能作废重跑,无法区分「实习生跑砸了」还是「竞品真的弱」。系统性自家偏向只能被兜底手段削弱、不能被证伪。若日后发现偏差污染榜单,再引入「同题双人跑」作为升级路径(本 ADR 不预建)。
