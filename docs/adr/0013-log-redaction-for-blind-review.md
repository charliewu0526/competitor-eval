# 执行日志包拆脱敏版 / 原始版,以同时守住盲评与证据完整

多人系统强制上传「执行日志包」(执行时间线 + token 花销 + 调用次数),它一物两用:既是喂评审面板的过程证据,又是 `cost_source` 的真实来源。但日志几乎必然泄露产品身份(token 量级反推模型、日志格式/进程名/自称品牌),与「提交后打乱标签盲评」冲突——标签盲了,日志没盲,面板一读就知道谁是自家。反过来,若把日志洗得太干净又会削弱证据(token 数被抹掉就没法算成本)。

决定:一份日志派生两个视图。**脱敏版**(洗掉品牌/模型指纹/自称,保留过程结构与相对量级)喂盲评面板;**原始版**(完整 token/调用/时间线)只给成本统计模块和人工抽查——这两个消费者本来就知道谁是谁,不受盲评约束。

## 代价

需要一个脱敏步骤(规则化洗品牌词/模型名/URL/进程指纹)夹在提交与送审之间,且要审计脱敏是否洗漏(漏一个品牌词就破盲)。脱敏规则本身成为需要维护的资产。
