# 第一版切最薄闭环,先验证「实习生模式」成不成立

grill 定的九条加起来是好几个月的工程(上服务器、鉴权、文件上传、脱敏流水线、三级权限、版本保鲜……)。一次性全做 = 迟迟上不了线,而「实习生模式」本身有个未验证的假设:新人跑竞品能否产出可用数据(执行偏差残余风险,ADR-0015)——这只有真有人用了才知道。

决定第一版只做**最薄的能转起来的闭环**:实习生注册 → 领任务(Assignment)→ 提交交付物+执行日志包 → 数据进现有评测引擎 → 出能力域榜单。刻意砍到人工代替的:①脱敏(先人工洗日志再送审,不做自动脱敏流水线)②方法复核闸(先口头/线下把关,不做系统闸)③自动 stale 判定(先人看测试日期,不做后台自动标灰)。目标:两三周内让 1-2 个实习生真跑一道对比任务,验证模式成立,再拿真实使用逼出剩余八条的优先级。呼应立身之本「先搭框架机制,再填内容深度」。

## 代价

MVP 上线时脱敏靠人工 = 有洗漏破盲的风险(可接受,量小);方法导出无系统门禁 = 靠自觉(可接受,人少)。这些「人工代替」项必须显式登记为技术债,不能因为「先跑起来了」就忘记补。若模式验证失败(实习生数据不可用),及时止损,不硬推完整系统。
