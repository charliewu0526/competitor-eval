# ADR-0003 — 任务库分层：留 tier 字段，第一版只填 core-common

- 状态：已接受
- 日期：2026-06-24
- 关联：ADR-0002（层级推导解决「够不到」不公平）

## 背景

原始风险②：同一任务对 A 是核心场景、对 B 是边缘场景，硬比会误导。提出四层任务库。
澄清：分层解决的是「定位差异」不公平；「够不到」不公平已由 ADR-0002 层级推导解决，二者不同。

## 决策

给 `TaskSpec` 加 `tier` 字段，取值 `core-common` / `vio-key` / `rival-signature` / `stress`。
第一版**只填充 `core-common` 一层**；其余三层先定义、不填充。

## 理由

1. **提前留缝比事后凿缝便宜**：字段现在加几乎零成本；不加则以后所有任务回头补。
2. **core-common 最公平、最适合校准引擎**：第一版目标是把评测引擎跑顺、证明能产出可信分数；核心共同任务最无争议。
3. **rival-signature / stress 的公平判断本身更难**，应在引擎校准可信后再碰。

## 后果

- `TaskSpec.tier` 枚举四值，v1 数据只出现 `core-common`。
- 引擎可信后再向其余三层扩展。
