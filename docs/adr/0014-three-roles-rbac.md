# 三级角色:实习生 / 审核员 / PM——校准开关只归 PM

多人系统上线后,"谁能复核报告、谁能触发黄金集重校准"必须显式定义。两级(只有 PM + 实习生)会让 PM 成为所有大差距报告的复核瓶颈,退回「人在每环节签字」的老问题;而让实习生互相复核又把「抽查判异常 → 评委降权重校准」这个危险开关交给了还在被培训的新人。

决定设三级角色(RBAC):
- **实习生 (intern / Runner)**:领任务、执行、提交交付物。不能复核,更不能碰校准。执行与复核职责分离(不能复核自己执行的任务)。
- **审核员 (reviewer-human)**:PM 信任的资深执行者。可对分派给自己的复核任务下「有道理 / 有问题」结论。**但不能触发黄金集重校准、不能改评委权重**——复核结论只是数据,校准是另一道闸。
- **PM (owner,charlie)**:全权。掌黄金集校准、评委授权/降权、任务清单、脱敏规则。

## 代价

需要一套最小 RBAC(注册即 intern,PM 手动提升为 reviewer)。审核员的复核结论如何影响下游(是否自动进入校准候选池,还是仅标记待 PM 定夺)需在实现时定清——本 ADR 只锁定「审核员不能自行触发校准」这条边界。
