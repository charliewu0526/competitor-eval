# ADR-0007 — 第二条评测路径：能力专项对比 + 开源代码机理分析

- 状态：已接受
- 日期：2026-06-24
- 关联：ADR-0001（情报砍到 v2）、ADR-0004（评分）、原始风险④

## 背景

原五条预分类规则全是「任务驱动」——出公共题、比分数。盲区：竞品的差异化卖点（如「省 token」、某新功能）很可能不在我们的任务库里，等它出现在公共题里才发现 = 永远发现不了。

## 决策

引入与「任务考试」并列的**第二条评测路径：能力专项对比 (capability probe)**。

1. **专项对比**：针对竞品某个卖点，专门设计探针任务，拿它的该能力 vs Vio 对应功能直接对打。
2. **开源代码机理分析**：若竞品开源（如 Open Interpreter），读源码搞清它「怎么做到的」，作为产品机会的机理证据（黑箱→白箱）。
3. **判断链路**（接风险④闸门）：
   卖点 → ①专项对比(差多少) → ②若开源读码(怎么做到) → ③风险④判断闸(解决啥问题/核心还是噱头/高频吗/我们用户要不要) → ④填「产品判断」字段。

## 范围边界

- v1 做「专项对比」路径，但**触发靠 PM 手动指定**（"测一下省 token"）。
- **自动全网抓竞品卖点** 仍归 v2 情报 pipeline（守 ADR-0001 范围纪律）。

## 后果

- 任务模型需支持 `kind: task-exam | capability-probe`。
- 开源竞品登记表加字段标记 repo 可分析。
