# 分数绑定竞品版本号 + 测试日期,超期自动标陈旧

竞品(Manus/Codex/Kimi)飞速迭代,榜单是时间快照。若不标日期:3 月测 Manus 得 60,6 月 Manus 翻倍但榜上仍挂 60 → 榜在用过时数据告诉研发「我们领先」,现实可能已反转;更糟是同域内 Violoop 是本周分、竞品是三个月前分,拿今天的自己比过去的对手,赢了是假赢。竞品情报系统烂掉,多数不是算法错,是数据过期还被当现状用(data staleness)。

决定:每条分数(RunRecord/score)绑定 **竞品版本号 + 测试日期**;榜单显式标「截至 X 日」;超过 N 天(默认待定,建议 90 天)的分数**自动标为陈旧 (stale)**,提示需重测,不再冒充现状。

## 代价

需要采集竞品版本号(部分闭源产品版本不透明,可能只能记「测试日期 + 抓到的 build 标识」)。需要一个后台判定 stale 的机制 + 榜单的陈旧态渲染。重测有人力成本,N 天阈值要在「新鲜度」与「重测负担」间调。schema 需加 competitor_version / tested_at / stale 字段(实现时落 F1)。
