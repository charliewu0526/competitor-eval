# 修复 Agent 作用域:低危白名单 + 硬禁区

即便提交者已限制为登录用户(ADR-0020),反馈文字与截图仍是「人写的自由文本/图像」,会被 AI 读进去当指令——AI 又有写权限、能跑命令,必须有物理边界。

决定用**白名单 + 硬禁区**画界,不给全仓写权限:AI **只允许改**前端组件/页面/样式/文案/纯展示逻辑这类「错了也只是界面坏、不伤数据不破安全」的低危区;**硬禁区**:鉴权/RBAC(登录与角色)、DB schema/迁移、脱敏规则、删数据的代码、`.env`/secrets、部署脚本。碰禁区 → 不自动改,转人工并说明原因。

这条同时是**最强的 prompt-injection 护栏**:注入指令(含截图里藏的文字)再花哨,也越不出「只能改低危文件」这道物理边界;最坏后果只是某页面坏,而冒烟金丝雀(ADR-0023)会当场拦下自动回滚,伤不到数据/鉴权/密钥。依据现实:用户说的「简单/阻塞小问题」绝大多数落在前端展示层。真正碰核心逻辑/数据/安全的 bug 本就该 owner 亲手过,AI 转人工正合适。
